# Contributing Guidelines

## How to Contribute

We appreciate your interest in contributing to the Inspire Healthcare Portfolio! Here are the guidelines:

### Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/your-username/inspire-healthcare-portfolio.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Commit with clear messages: `git commit -am 'Add feature: description'`
6. Push to your fork: `git push origin feature/your-feature-name`
7. Submit a Pull Request

### Code Style Guidelines

#### HTML
- Use semantic HTML5 elements
- Always include alt text for images
- Use lowercase for tags and attributes
- Indent with 2 spaces

#### CSS
- Use CSS variables for colors and sizes
- Follow BEM naming convention for classes
- Mobile-first approach
- Use comments to section code
- Indent with 2 spaces

#### JavaScript
- Use const/let instead of var
- Add comments for complex logic
- Follow camelCase for variable names
- Use arrow functions when appropriate
- No console.logs in production code

### Commit Message Format

```
<type>: <subject>

<body>

<footer>
```

**Type:**
- `feat:` A new feature
- `fix:` A bug fix
- `docs:` Documentation only changes
- `style:` Changes that don't affect code meaning
- `refactor:` Code change that neither fixes bug nor adds feature
- `perf:` Code change that improves performance
- `test:` Adding missing tests

**Examples:**
```
feat: Add appointment booking form
fix: Resolve carousel navigation on mobile
docs: Update README with setup instructions
```

### Pull Request Process

1. Update README.md with any new features or changes
2. Test your changes thoroughly (all browsers and screen sizes)
3. Include screenshots for UI changes
4. Describe the changes clearly in PR description
5. Link related issues if applicable
6. Ensure all tests pass

### Issues & Bug Reports

When reporting issues:
1. Use a clear, descriptive title
2. Describe the exact steps to reproduce
3. Include screenshots/recordings
4. Mention your browser and device
5. Include browser console errors

### Feature Requests

1. Check if feature already exists
2. Provide use cases and benefits
3. Include mockups or examples
4. Be open to discussion and feedback

### Code Review

- Be respectful and constructive
- Focus on code quality and maintainability
- Suggest improvements, don't demand
- Approve when code meets standards

## Thank You!

Your contributions make this project better! 🙏
